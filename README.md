# ScienceLine — Наука поруч

Курсова робота з дисципліни «Веб-технології та веб-дизайн», варіант №1 — науково-популярний новинний портал. Резников Володимир Іванович, АІ-231.

Репозиторій: [D0zz1/ScienceLine](https://github.com/D0zz1/ScienceLine). Версія подання: **v1.0.2**. Файли цієї версії доступні за відповідною Git-позначкою.

Працездатний ASP.NET Core MVC застосунок із PostgreSQL, EF Core migrations, ASP.NET Core Identity та локальною копією Bootstrap 5.3.8. Це навчальна редакція: початкові статті й облікові записи демонстраційні, ілюстрації — власні SVG-схеми. Публічна статична копія не використовується замість backend.

## Що реалізовано

- Публічний каталог, сторінка матеріалу, пошук у назві й основному тексті, фільтр рубрики та пагінація.
- Автор зберігає власну чернетку, надсилає редактору та виправляє повернений матеріал.
- Редактор публікує матеріал або повертає з обов'язковим поясненням; рішення пов'язане з версією тексту та виконавцем.
- Історія незмінних текстових версій і порівняння рядків за алгоритмом LCS.
- Перевірка ролі та власника на сервері, глобальна CSRF-перевірка POST, валідація посилань і зовнішніх ключів, optimistic concurrency та унікальний ключ повторного створення.
- Читання каталогу лише зі статусом Published; приватний матеріал за публічним URL повертає 404.

## Вимоги

Перевірене локальне середовище: Windows x64, .NET SDK 10.0.403, PostgreSQL 17.11, Python 3 (для HTTP-тестів), Node.js + Playwright та Microsoft Edge (для браузерних перевірок). .NET 10 — стабільна цільова платформа; проєкт не використовує preview SDK. Версії залежностей зафіксовано в csproj, packages.lock.json і локальному маніфесті dotnet-ef.

## Запуск із наявною PostgreSQL

Створіть окрему БД і користувача за допомогою адміністратора PostgreSQL. Наведені нижче значення паролів потрібно замінити; приклади не є чинними обліковими даними.

```sql
CREATE ROLE scienceline LOGIN PASSWORD 'REPLACE_WITH_RANDOM_DATABASE_PASSWORD';
CREATE DATABASE scienceline OWNER scienceline;
```

У PowerShell 7 із кореня репозиторію:

```powershell
$env:ConnectionStrings__Portal='Host=127.0.0.1;Port=5432;Database=scienceline;Username=scienceline;Password=YOUR_DATABASE_PASSWORD'
$env:ASPNETCORE_ENVIRONMENT='Development'
$env:ASPNETCORE_URLS='http://127.0.0.1:5180'
$env:Demo__Enabled='true'
$env:Demo__Password='YOUR_RANDOM_DEMO_PASSWORD_Aa1'
./scripts/run.ps1
```

Пароль демо має містити щонайменше 12 символів, великі й малі латинські літери та цифру. Команда відновлює пакети, збирає застосунок, застосовує міграції й запускає backend. Відкрийте **http://127.0.0.1:5180**. `/health` підтверджує роботу HTTP-процесу; стан БД перевіряють запитом до каталогу або SQL.

Для лише створення схеми: `./scripts/run.ps1 -MigrateOnly`. SQL для перевірки схеми: `docs/sql/schema.sql`. Після зміни моделі створюйте нову міграцію командою `dotnet ef migrations add NAME --project src/ScienceLine.Web`, а не редагуйте вже застосовану міграцію.

## Альтернативний Docker Compose

```powershell
./scripts/new-demo-env.ps1
docker compose up --build -d
docker compose logs web
```

У `.env` згенеровано окремі випадкові паролі БД та демонстраційних користувачів. Відкрийте той самий локальний URL. `docker compose restart web` перезапускає backend зі збереженням БД. `docker compose down` зупиняє контейнери, томи зберігаються. Не видаляйте томи, якщо потрібні ваші дані.

Compose додано як інструкцію розгортання; у зафіксованому середовищі Docker не встановлено, тому наведені результати тестування отримано нативним запуском Windows, а не контейнерами. Development і HTTP дозволені тільки для локальної демонстрації; публічне розгортання потребує Production, HTTPS, точного AllowedHosts, резервних копій та захисту каталогу ключів.

## Демонстраційні ролі

| Пошта | Роль | Призначення |
|---|---|---|
| author@scienceline.example | Author | Власні матеріали й версії |
| second@scienceline.example | Author | Перевірка ізоляції чужих чернеток |
| editor@scienceline.example | Editor | Редакційна черга та публікація |
| reader@scienceline.example | Reader | Читання без редакторських прав |

Пароль усіх демо-користувачів задається лише через `Demo__Password`. У репозиторії, звіті та відео чинних паролів немає. Для власного запуску ви генеруєте їх самі. Публічна реєстрація завжди створює Author; роль Editor через форму не призначається. Демо-ініціалізація ідемпотентна й не скидає пароль уже створеного користувача. Для production вимкніть Demo; провізіонування редактора виконує адміністратор окремою контрольованою процедурою.

## Наскрізна перевірка вручну

1. Автор: «Мої матеріали» → «Новий матеріал». Заповніть назву, опис, текст, джерело http/https, рубрику та альтернативний текст ілюстрації. Збережіть чернетку.
2. В окремому неавторизованому вікні публічний `/articles/ID` має повернути 404. Інший автор не бачить `/author/ID` та `/history/ID`.
3. Надішліть матеріал на перевірку. Редактор бачить його у черзі; автор не може змінювати текст під час перевірки.
4. Редактор повертає матеріал з коментарем. Автор бачить зауваження, виправляє текст, порівнює версії й надсилає знову.
5. Редактор публікує. Гість знаходить матеріал у каталозі; джерело, рубрика, автор та ілюстрація збережені.
6. Перезапустіть лише backend і відкрийте той самий ID. Стаття залишається в PostgreSQL.

## Автоматичні перевірки

Модульні тести не потребують БД:

```powershell
dotnet test tests/ScienceLine.Tests --logger 'trx;LogFileName=unit-tests.trx' --results-directory docs/evidence
```

HTTP-тести працюють із реальною PostgreSQL і вже запущеним демо-застосунком. Створіть локальний файл `.local/settings.json` (він ігнорується Git), указавши **власні** параметри:

```json
{"DbPassword":"YOUR_DATABASE_PASSWORD","DemoPassword":"YOUR_DEMO_PASSWORD","DbPort":5432,"AppPort":5180}
```

```powershell
python tests/http_integration.py --psql 'C:/Program Files/PostgreSQL/17/bin/psql.exe'
# Зупиніть і знову запустіть власний backend, зберігши ту саму БД.
# У .local/server.pid запишіть PID нового backend для журналу.
python tests/persistence.py
```

Тести створюють записи з префіксом E2E. Вони призначені для окремої навчальної БД і не повинні запускатися на production. Результати: `docs/evidence/http-results.json`, `unit-tests.trx`, `persistence.json`. Підтверджений запуск: **41 HTTP-перевірка, 13 модульних, 8 браузерних; усі пройдено**. Збереження після фактичного перезапуску підтверджено окремо. Значення часу описані в JSON; це loopback на малому наборі даних, а не вимірювання місткості production-сервера.

Браузерні перевірки потребують установленого `playwright`: виконайте `pnpm --dir tests install --frozen-lockfile`. За потреби задайте `BROWSER_EXECUTABLE` на Chromium/Edge; CODEX_NODE_MODULES підтримує окреме середовище пакетів. Команда: `node tests/browser-check.cjs`. Вона створює окремий headless-контекст, перевіряє адаптивність 390px і зберігає справжні PNG. Скрипт не читає інші вікна й не керує робочим столом.

## Структура

`src/ScienceLine.Web` — MVC, domain models, DbContext, migrations, business workflow, Razor Views, local assets. `tests` — відтворювані автоматичні перевірки. `docs/sql` — схема БД. `docs/diagrams` — ER, архітектура, бізнес-процес. `docs/evidence` — результати реального виконання та екрани. Звіт і демонстраційне відео передаються окремими файлами разом із вихідним кодом.

## Межі рішення

Немає production-пошти, підтвердження email, MFA, завантаження довільних файлів, повнотекстового індексу чи автоматичної фактологічної перевірки. Ілюстрація вибирається з контрольованих локальних схем; редактор перевіряє зміст і джерело людиною. Знімок версії зберігає назву, короткий опис, основний текст і джерело, але не є повною історією всіх налаштувань статті. Порівняння обмежене 200 рядками. Зміни інтерфейсу не замінюють серверні перевірки.

Підготовка коду та пояснень виконувалася з допомогою інструментів генерації й перевірки. Журнал у `docs/development-notes.md` відокремлює автоматизацію від фактично виконаних тестів. Не заявляється непідтверджений відсоток самостійної роботи.

## Додаткові експерименти якості v1.0.2

Виконано шість конкурентних прогонів на 10 000 статей: 1/5/10 клієнтів, два повтори, 2 с прогріву та 10 с вимірювання. Під час навантаження вимірювалися CPU, приватна пам’ять і з’єднання БД. 45 141 виміряний запит, 0 помилок; гірші p95=25,55 мс та p99=28,61 мс. Заздалегідь установлені локальні пороги: помилки ≤1 %, p95≤500 мс, p99≤1000 мс. Це локальний експеримент на одному комп’ютері.

Обсяг: 100/1 000/10 000 статей із рубриками, тегами, версіями та різними станами; по 40 GET після п’яти прогрівальних для кожного маршруту. Перевірено пошук, фільтр, дві сторінки без дублів, точкове читання та створення чернетки з SQL-підтвердженням. Збережено EXPLAIN ANALYZE BUFFERS.

Frontend: три холодні контексти Edge для 1440×1000 і 390×844, емуляція 10 Мбіт/с, 40 мс, CPU×4. Медіанний LCP 688/652 мс, CLS=0. Відгук input→кадр та Event Timing записані окремо; вони не видаються за польовий INP. На 320/360/768/1440 px перевірено reflow, alt, назви полів та перший видимий клавіатурний фокус. Це визначений набір, без твердження про повну сертифікацію WCAG.

Усі вихідні зразки, ресурси, плани, умови, PNG і підсумок: `docs/evidence/quality/`. Робоча БД не збільшувалася: використано окремий клон. Початкові 13/41/8 функціональних перевірок і факт перезапуску наведено вище.

### Відтворення додаткових дослідів на Windows

Потрібні мігрована навчальна БД зі стандартними Demo-користувачами, приватна `.local/settings.json`, PostgreSQL psql/createdb, Python 3 і Node із pnpm. Для моніторингу використовуються штатні лічильники Windows. Зупиніть власний backend перед створенням клону; не використовуйте production БД. Скрипт не розриває сторонні з’єднання й не видаляє бази.

```powershell
pnpm --dir tests install --frozen-lockfile
./scripts/run-quality.ps1 -PgBin 'C:/Program Files/PostgreSQL/17/bin' -Python python -Node node
```

Скрипт створює нову БД `scienceline_quality_*`, приватні параметри, запускає окремий backend на 127.0.0.1:5181, виконує обсяг/навантаження й браузерні заміри та зупиняє тільки запущений ним backend. Вихідна навчальна БД не змінюється. Клон зберігається для перевірки. Порт 5181 має бути вільний. Якщо вихідна навчальна БД має понад 100 статей, використайте свіжий стандартний навчальний набір: тест обсягу зупиниться замість видалення даних.

Окремі команди: `python tests/quality_experiments.py --settings PRIVATE_JSON --psql PATH`; `node tests/frontend-quality.cjs`. Повторення лише навантаження на вже підготовлених 10 000 статтях: додайте `--only-load`. Для іншого браузера задайте BROWSER_EXECUTABLE. Playwright шукається у tests/node_modules; CODEX_NODE_MODULES може задати окреме середовище пакетів.

### Порівняння до та після поліпшень

30.10.2026 контрольовано прибрано і відновлено вже реалізований складений індекс тільки в ізольованому клоні з 10 000 статей. Медіана SQL-вибірки: 4,764 → 0,067 мс; HTTP-каталогу: 8,810 → 4,258 мс. Перші дев’ять записів збігаються; індекс відновлено, розмір 256 КіБ. Вартість вставки 100 рядків: медіани 4,019/4,071 мс, п’ять транзакцій у кожному стані з rollback. Умови й плани: index-comparison.json. Кеші прогріті, послідовний порядок може впливати на час.

Мінімізація офіційного Bootstrap 5.3.8 зменшує CSS із 280 311 до 232 111 байтів, на 17,2 %. Три холодні повтори кожного стану з чергуванням порядку дали медіанний LCP 448/456 мс; виграшу LCP цей дослід не підтвердив. Саме скорочення файла не прирівнюється до прискорення кадру. Перевірені ширина, шрифт і посилання однакові; дані — frontend-comparison.json.

Обидва порівняння включені в run-quality.ps1. Для окремого запуску на вже запущеному ізольованому backend: `python tests/optimization_comparison.py --settings PRIVATE_CLONE_JSON --psql PATH` та `node tests/frontend-comparison.cjs`. Параметр `-EvidenceDirectory` зберігає результати в іншій папці, наприклад `.local/quality-check`, без перезапису доданих доказів.
